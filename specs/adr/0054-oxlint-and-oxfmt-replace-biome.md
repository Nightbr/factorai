# ADR-0054 — oxlint and oxfmt replace Biome

**Status.** Accepted (2026-09-21). Supersedes the tooling line of
[ADR-0001](0001-stack-tauri2-react19-pnpm-biome.md) — "Biome 1.9 for lint +
format" — and nothing else in it: the shell, renderer, state and styling
choices there stand.

## Context

Biome 1.9.4 has been the single JS/TS/CSS lint and format gate since M0. It
works. What changed is that [oxc](https://oxc.rs) now ships both halves of the
same job — `oxlint` 1.83 for the lint side, `oxfmt` 0.68 for the format side —
with a rule set that is a superset of what we were gating on, a formatter that
agrees with our Biome output on 289 of 301 files, and a migration path that
reads `biome.json` directly: `oxfmt --migrate=biome` wrote every formatting
option in `.oxfmtrc.json`, and what we added by hand is the ignore list, the
CSS override and the comments saying why.

Three things made it worth doing now rather than later:

- **The gate is cheap to move while it is small.** The whole check list is
  seven root scripts and four package `lint` scripts. Every month of code
  written against Biome-specific suppression comments is another month of
  `// biome-ignore` to rewrite.
- **The rule sets have diverged in oxc's favour.** oxlint's `correctness`
  category alone catches the React Compiler family (`react/refs`,
  `react/set-state-in-effect`, `react/immutability`), which Biome 1.9 has no
  equivalent of and which fires 77 times in renderer code that works today.
  We are not turning those on in this commit — see below — but they are the
  reason to be on the tool that has them.
- **Speed, which is the least interesting reason and still real.** `oxlint`
  over `apps/desktop/src` is 71 ms for 207 files against 164 rules; `oxfmt
  --check` over the tree is 191 ms for 301 files.

## Decision

Replace `@biomejs/biome` with `oxlint` + `oxfmt`, both pinned exact at the root.

- **`.oxlintrc.json`** carries the lint contract. Every one of the six rules
  `biome.json` set by hand has a one-to-one counterpart and keeps its level:
  `no-unused-vars` (which covers unused imports, so the two Biome rules collapse
  into one), `typescript/no-explicit-any`, `typescript/no-non-null-assertion`
  at `warn`, `prefer-const`, `prefer-template`, and `no-restricted-globals` over
  `confirm` and `prompt` (specs/05-features.md § F17).
- **Five rules are added** to cover what Biome's recommended set reached past
  oxlint's `correctness` category: `eqeqeq` (with `null` excepted — `!= null` is
  the one-comparison undefined-or-null check and the codebase uses it),
  `no-var`, `react/no-array-index-key`, `react/jsx-no-useless-fragment` and
  `react/no-danger`. All five were already satisfied by the code.
- **`.oxfmtrc.json`** carries the format contract, generated by
  `oxfmt --migrate=biome`: tabs at width 2, print width 100, single quotes,
  semicolons, trailing commas everywhere. Scope stays what Biome's was —
  JS/TS/CSS — with JSON, Markdown, YAML and TOML in `ignorePatterns`, because
  oxfmt formats those natively and letting it would rewrite every spec in the
  repo in the same commit as a toolchain change.
- **`pnpm lint` keeps its shape**: `turbo lint`, one `oxlint src` per package.
  A single root `oxlint` would now be fast enough to replace the fan-out, and
  would cover `tests/` and `scripts/` for the first time. That is a change to
  what is linted, not to what lints it, so it is not in this commit.

**Two rule families are deferred, not dropped, and `.oxlintrc.json` says so
beside each.** The React Compiler rules (77 findings) and four `jsx-a11y` rules
stricter than Biome's recommended a11y set (9 findings) are off. Turning them on
means changing renderer behaviour, which is item 60's work, not a toolchain
commit's.

## Consequences

**Positive.**

- One fewer vendor in the gate that is not also the bundler's family: oxc is
  what Vite's own toolchain is converging on.
- The lint floor is strictly higher than it was — five rules added, none
  removed — and the config now states the reason beside every rule it turns
  off, the same rule `knip.jsonc` has lived under since 2026-08-15.
- `oxfmt --check` prints every file it would rewrite. Biome capped at 20
  diagnostics by default and a 32-file backlog read as a 20-file one.

**Negative.**

- **oxfmt is pre-1.0** (0.68). It is the newer half of this by a wide margin,
  and a formatter that changes its mind between versions rewrites the repo. The
  pin is exact and a bump is a diff to read, not a version to trust.
- **One-time churn in 12 files**, all of it style: CSS multi-value properties
  break one per line, CSS strings become single-quoted, and a handful of TS
  signatures re-wrap. Nothing else moved.
- **Suppression comments are not interchangeable.** Four `// biome-ignore`
  became `// oxlint-disable-next-line`, and three more sites needed one that
  Biome had never asked for. `react-hooks/exhaustive-deps` **did not honour a
  suppression comment at all** in 1.83 — neither above the hook nor above the
  line it flags, in either the `oxlint-` or the `eslint-` spelling — so the one
  site that needed it (`AppShell`) was fixed properly instead, by pulling the
  four `viewer` fields the effect reads out of the object the hook re-creates
  every render.
- Import sorting is still not gated. Biome's `organizeImports` was on in
  config and never ran, because the gate called `biome format`, not
  `biome check`. `oxfmt`'s `sortImports` would rewrite 181 files; that is its
  own commit if we want it.
